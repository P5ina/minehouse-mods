# MineHouse (клиентский мод)

Единственный наш клиентский мод для сборки MineHouse (Fabric 26.3), jar `minehouse-client.jar`,
fabric id `minehouse-client`. До сборки 1.14.0 это были четыре мода: MineHouse Menu, Anvil Client,
Events Editor и Zones Client. Каждая часть живёт в своём пакете со своей точкой входа
(`entrypoints.client` в `fabric.mod.json`), каналы с сервером и папки ассетов
(`minehouse-menu`, `minehouse-events-editor`) остались прежними, так что серверу ничего менять не
нужно. Новые клиентские фичи добавляй сюда же, отдельный jar не заводи.

| Пакет | Что делает |
|---|---|
| `pro.minehouse.menu` | главное меню, автообновление, интро, гардероб и косметика, ники, тихая вагонетка |
| `pro.minehouse.anvilclient` | настоящая цена в окне наковальни |
| `pro.minehouse.zonesclient` | границы зон спавна линиями и стенами |
| `pro.minehouse.eventseditor` | редактор шоу для админов (клавиша K) |
| `pro.minehouse.riftclient` | режим «Разлом»: вид сверху, курсор, управление, интерфейс режима; картинка разлома |

## Меню

Меняет главное меню:

- логотип MineHouse вместо Minecraft;
- первая кнопка «▶ Играть на MineHouse» сразу подключает к серверу, под ней онлайн
  (пинг раз в 30 секунд);
- «Одиночная игра» и «Сетевая игра» в одном ряду, вместо Realms кнопки «Сайт» и
  «Discord»;
- свои сплэши (`assets/minecraft/texts/splashes.txt`).
- тихая вагонетка (флаг `Silent`, на сервере это вагонетка с именем «Тихо») не стучит и для
  того, кто в ней сидит: ванильный звук изнутри (`RidingMinecartSoundInstance`) флаг не проверяет.

- автообновление сборки, как у Essential: ещё до загрузки Minecraft (Fabric `preLaunch`,
  `PreLaunchUpdate`) мод сверяется с `https://www.minehouse.pro/modpack/manifest.json`.
  Если сборка изменилась, открывается небольшое окно MineHouse (`UpdateWindow`, отдельный
  Java-процесс на Swing, чтобы игра не трогала AWT) с прогрессом и кнопкой «Пропустить»;
  файлы проверяются по sha512. Файлы вне `mods/` встают сразу. Изменённые моды заняты
  игрой, поэтому игра закрывается, `UpdateApplier` подменяет jar и запускает игру снова той
  же командой (если игра стартовала прямо в `KnotClient`: наш лаунчер, официальный). Prism
  и похожие лаунчеры передают параметры через stdin, там окно просит запустить игру ещё раз
  (или «Играть без него», тогда обновление встанет после выхода). Нет связи с сайтом за 6 с
  или окно не открылось: старое поведение, фоновая докачка и подмена после выхода.
  Список установленных сборкой файлов лежит в `config/minehouse-pack.json`, чужие моды
  игрока не трогаются. Без этого файла (dev-запуск) обновление выключено.

Адрес сервера и ссылки в `config/minehouse-menu.properties` (сборка кладёт его
сама, `discord.url` пустой = кнопки Discord нет).

## Наковальня (`pro.minehouse.anvilclient`)

Клиентский Fabric-мод для сборки MineHouse. Показывает в окне наковальни настоящую цену
работы вместо 39 и без «Слишком дорого!».

### Зачем

На сервере стоит [MineHouse Anvil](../anvil-mod): у наковальни нет лимита в 40 уровней.
Ванильный клиент при цене от 40 пишет «Слишком дорого!», поэтому сервер отправляет ему
не больше 39, а настоящую цену пишет над хотбаром. С этим модом сервер присылает
настоящую цену пакетом `minehouse:anvil_cost`, и она видна прямо в окне: «Требуемый
уровень: 58», красным, если уровней не хватает. Надписи над хотбаром тогда нет.

Сервер узнаёт о моде по зарегистрированному каналу (Fabric API), игрокам без мода всё
работает как раньше. На других серверах мод ничего не меняет: пакет не приходит, окно
ванильное.

### Как устроено

- `AnvilCostPayload`: пакет (id окна, цена), такой же класс лежит в `anvil-mod`.
- `AnvilCost`: последняя цена от сервера. Ей верим, только пока в окне стоит то, во что
  сервер её урезал (`min(цена, 39)`): сразу после перекладывания предметов клиент сам
  пересчитывает цену по ванильным правилам, и до ответа сервера показывается она.
- `AnvilScreenMixin`: в `extractLabels` подменяет цену, убирает порог 40 и считает цвет по
  настоящей цене.

## Зоны спавна (`pro.minehouse.zonesclient`)

Клиентский Fabric-мод для сборки MineHouse. Рисует границы зон спавна линиями и
полупрозрачными стенами вместо частиц.

### Зачем

Зоны спавна живут в [MineHouse Bank](../bank-mod) (пакет `zones`). Когда админ держит палку
«Разметка зон» или игрок пишет `/zones show`, сервер показывает границы. Без мода это
частицы на высоте игрока. С модом сервер присылает пакет `minehouse:zone_shapes` с
многоугольниками, и клиент рисует:

- полупрозрачную стену по каждой стороне зоны, от нижней до верхней высоты зоны;
- сплошные линии снизу и сверху, тонкие каждые 10 блоков и линию на уровне ног игрока;
- столбы в углах и название зоны над серединой;
- у черновика админа (фиолетовый) пронумерованные вершины.

Цвета как на сайте и BlueMap: оранжевая — аукцион, зелёная — свободна, красная — арендована,
бирюзовая — твоя, белая — общая. Дальше 160 блоков ничего не рисуется.

Рисуется ванильными гизмо (`net.minecraft.gizmos`), без миксинов. Сервер узнаёт о моде по
зарегистрированному каналу (Fabric API) и шлёт пакет только когда набор зон меняется. На
других серверах мод ничего не делает.

### Как устроено

- `ZoneShapesPayload`: пакет со списком зон, такой же класс лежит в `bank-mod`.
- `ZoneRenderer`: каждый тик кладёт линии, стены и подписи в `Minecraft.collectPerTickGizmos()`.
- `SelfTest`: проверка для CI.
- `Demo`: только для разработки, рисует выдуманные зоны и делает скриншот.

## Разлом (`pro.minehouse.riftclient`)

Клиентская половина режима [«Разлом»](../rift-mod/README.md); без неё сервер режима не пускает
(признак мода для сервера — то, что клиент слушает канал `minehouse-rift:view`).

- Сервер присылает `RiftViewPayload`: включить вид сверху (угол поворота, наклон, расстояние)
  или вернуть обычный. При выходе с сервера вид возвращается сам.
- `TopDown` — вся геометрия числами, без игры (юнит-тесты `TopDownTest`): камера над игроком
  с узким углом обзора, мышь двигает курсор по экрану (сама мышь остаётся захваченной),
  персонаж поворачивается к точке под курсором, W, A, S, D ведут по экрану, а не туда, куда
  смотрит персонаж.
- Клик действует на то, что под курсором: левый бьёт моба под курсором, а если там никого,
  то ближайшего в пределах удара и ±60° от взгляда; правый открывает блок под курсором.
  Луч курсора проходит сквозь барьеры и блоки света (ими сделаны крыша и свет в залах).
- Миксины (`minehouse-rift-client.mixins.json`): `Camera` (положение и угол обзора),
  `MouseHandler.turnPlayer` (курсор вместо поворота головы), `KeyboardInput.tick` (ходьба по
  экрану, перекат вместо прыжка), `Minecraft.startAttack/startUseItem` (цель клика).
- В том же пакете приходит «упал»: пока напарник не поднимет, персонаж ползёт (поза своего
  игрока выбирается на клиенте, поэтому серверу мало выставить её у себя).
- Упавший игрок (`DownedAnim`, миксин `PlayerModel.setupAnim`): своя анимация вместо плавательных
  гребков. Падает, раскинув руки, лежит, прижав одну руку к телу, ползёт, подтягиваясь другой рукой,
  ноги волочатся. Работает для себя и напарников (в забеге, поза ползания не в воде).
- Интерфейс режима (`RiftHud`, `PartyScreen`, `Ui`; каналы `minehouse-rift:note`, `lobby`,
  `action`, `roster`, `run`, `result`): сообщения режима не идут в чат.
  - Лобби (`PartyScreen`) открыто всё время, пока игрок в лобби, поверх сцены с платформами (фон
    не затемняется). Слева игроки на сервере с кнопкой «Позвать» и поле ника, справа отряд, режим,
    подбор и большая «Готов», сверху «На выживание» и «Покинуть отряд». Esc открывает меню игры,
    после него лобби возвращается; клавиша чата открывает чат. Ванильный HUD в лобби скрыт.
  - Забег: сверху зал и волна, имя и полоса босса; слева напарники; слева внизу своё здоровье
    вместо сердечек и брони; лента событий справа. Упавший видит красную рамку, «ТЫ УПАЛ», полосу
    до выбывания и кто его поднимает; напарник видит подсказку про Shift и полосу поднятия.
  - Итоги: поверх игры до возврата в лобби, карточка на каждого (убито, поднял, падал).
  - Цвета, плоские кнопки и полосы в `Ui`. Всё рассчитано на экран от 427×240 единиц интерфейса.
- Бой (`Combat`; каналы `minehouse-rift:cast`, `cooldown`, `warn`): в забеге клавиша прыжка
  делает перекат туда, куда ведут W, A, S, D (стоя на месте — куда смотрит персонаж), клавиша
  «выбросить» (Q) — «Волна», клавиша инвентаря (E) — «Осколок». Прыжка, выбрасывания и инвентаря
  в виде сверху нет. Решает всё сервер, мод только просит и показывает: четыре ячейки справа от
  хотбара (удар, перекат, волна, осколок) с подписью клавиши, как она назначена у игрока, и
  отсчётом перезарядки; красный круг на полу, который заполняется к моменту удара Стража.
- Камера лобби (`minehouse-rift:scene`): сервер присылает точку и угол, вид держит мод (как и вид
  сверху, через `RiftCameraMixin`), без наблюдения за сущностью.
- Звук (`RiftSoundMixin`): при виде сверху игра слушает с места персонажа, а не из камеры, которая
  висит в двадцати блоках.
- Удар и голод: слот «Удар» закрывается на время ванильного кулдауна оружия
  (`Combat.strikeCovered`), прицел на полу тускнеет до полного удара; полоски еды в забеге нет,
  голода в режиме нет.
- Экранные эффекты (`RiftFx`, `RiftFxMixin`; `assets/minehouse-rift/post_effect/*.json` и один
  шейдер `shaders/post/rift.fsh`): ванильная цепочка пост-эффектов, мод просит свой эффект там же,
  где игра спрашивает эффекты игрока (`GameRenderer.update`). Четыре набора настроек одного
  шейдера: `rift` (забег: фиолетовые края, лёгкое расхождение цветов у края), `rift_low` (здоровья
  35% и меньше: красный пульсирующий край, цвета блёкнут), `rift_downed` (упал: почти серо, красный
  край), `rift_lobby`. На интерфейс эффект не ложится. В шейдерах 26.3 подключение файлов —
  `#include <minecraft:globals.glsl>`, не `#moj_import`.
- `assets/minehouse-rift/` — анимированная картинка разлома (та же, что в ресурспаке
  выживания): на сервере режима ресурспак не качается.

## Редактор шоу (`pro.minehouse.eventseditor`)

Клиентский Fabric-мод: редактор шоу для [MineHouse Events](../events-mod/README.md). Входит в сборку
MineHouse, но работает только у админов: сервер говорит с
ним, только если у игрока есть право `minehouse.events.command` (или оператор 2+).

Сервер хранит шоу и проигрывает предпросмотр, мод только показывает и отправляет правки (канал
`minehouse:show_editor`, по одному JSON на пакет). Как пользоваться — в README серверного мода,
раздел «Редактор».

```
EditorClient     состояние сессии с сервера, выбор, отправка операций
EditorScreen     таймлайн и панель свойств
ShowPickerScreen K вне редактора: выбрать или создать шоу
CueSchema        поля и значения по умолчанию для каждого действия и актёра
WorldOverlay     сцена, места и пути камеры в мире
EditorHud        строка сверху, когда панель спрятана
```

## Сборка и проверка

```sh
./gradlew build                                         # jar + юнит-тесты
xvfb-run ./gradlew runSelftestClient                    # меню: скриншот титульного экрана, MINEHOUSE_MENU_OK
xvfb-run ./gradlew runSelftestClient -Pselftest=anvil -PselftestDir=run-selftest-anvil    # MINEHOUSE_ANVIL_CLIENT_OK
xvfb-run ./gradlew runSelftestClient -Pselftest=editor -PselftestDir=run-selftest-editor  # MINEHOUSE_EVENTS_EDITOR_OK
xvfb-run ./gradlew runSelftestClient -Pselftest=zones -PselftestDir=run-selftest-zones    # MINEHOUSE_ZONES_CLIENT_OK
xvfb-run ./gradlew runSelftestClient -Pselftest=rift -PselftestDir=run-selftest-rift      # MINEHOUSE_RIFT_CLIENT_OK
```

Проверка: `xvfb-run ./gradlew runSelftestClient` открывает игру, ждёт на
титульном экране, сохраняет `run-selftest/screenshots/minehouse-menu.png` и
пишет в лог `MINEHOUSE_MENU_OK`. Логотип собран из `public/brand/logo-mark.png`
и шрифта Unbounded.

Картинка зон: запусти любой сервер 26.3 на localhost:25565 (`online-mode=false`,
`white-list=false`, Steve в `ops.json`), потом `./gradlew runDemoClient`. Скриншоты лягут в
`run-demo/screenshots/`.

Поменял мод: `./gradlew build && cp build/libs/minehouse-client-*.jar ../modpack/minehouse-client.jar`,
подними `version` в `gradle.properties` и в `modpack/pack.json`.
